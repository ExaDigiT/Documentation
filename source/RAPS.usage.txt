usage: raps [-h] {run,run-parts,show,workload,telemetry,download,train-rl,shell-completion} ...

ExaDigiT Resource Allocator & Power Simulator (RAPS)

subcommands:
  run                Run a single-partition (homogeneous) system: synthetic workload or
                     telemetry replay, power model, optional cooling and network models
  run-parts          Run a multi-partition (heterogeneous) system
  show               Print the given CLI arguments as a YAML sim config
  workload           Generate a workload and save it as an .npz snapshot
  telemetry          Analyze a telemetry dataset (e.g. average job arrival time)
  download           Download telemetry data for a system
  train-rl           Train a reinforcement learning scheduler
  shell-completion   Register shell tab completion

Selected options of "raps run" (see "raps run -h" for the complete list):

  config_file           YAML sim config file, can be used instead of CLI flags. "-" reads stdin
  -c, --cooling         Include the FMU cooling model
  --net, --simulate-network
                        Include the network model
  --weather             Include weather in the cooling model (default: on for replay with cooling)
  --start, --end        Start / end of the simulation (ISO 8601); give either --end or --time
  -t, --time            Length of simulation: 123, 27m, 3h, 7d (default 1h)
  --ff, --fastforward   Skip this amount of time from the start of the dataset
  --time-delta          Step size of the power simulation (default 1s)
  --time-unit           Base tick of the job scheduler (default 1s)
  -n, --numjobs         Number of jobs for synthetic workloads (default 100)
  --seed                RNG seed for deterministic simulation
  -o, --output          Output directory (default raps-output-<id>); "none" disables output
  -p, --plot            power, loss, pue, temp, util, net
  --imtype              png, svg, jpg, pdf, eps
  -d, --debug           Debug mode, disables the rich layout
  --noui                Run without the UI
  -v, --verbose         Verbose output
  --layout              layout1, layout2 (layout2 is used automatically with cooling)
  -f, --replay          joblive,jobprofile directories, dataset file, or .npz snapshot
  --dataloader          Python module to use as a custom dataloader
  --power-scope         chip (CPU/GPU utilization, default) or node (node power)
  --jid                 Replay a single job id
  --scale               Scale replayed jobs to a smaller system (max nodes per job)
  --encrypt             Encrypt sensitive telemetry
  -w, --workload        random, benchmark, peak, idle, synthetic, multitenant, replay,
                        randomAI, network_test, inter_job_congestion, calculon, hpl
  --jobsize-*, --walltime-*, --cpuutil-*, --gpuutil-*
                        Distribution (uniform, weibull, normal) and parameters for synthetic jobs
  --multimodal          Mixture weights across the listed distributions
  --scheduler           default, experimental, fastsim, multitenant, scheduleflow
  --policy              replay, fcfs, priority, sjf, ljf (plus scheduler specific policies)
  --backfill            firstfit, bestfit, greedy, easy, conservative
  --arrival             prescribed (original submit times) or poisson
  --job-arrival-time    Poisson mean inter-arrival time in seconds
  --job-arrival-rate    Scale the Poisson rate
  --continuous-job-generation, --maxqueue
                        Keep generating jobs so the queue never runs dry
  --downtime-first, --downtime-interval, --downtime-length
                        Schedule periodic system downtimes
  --accounts, --accounts-json
                        Track per-account statistics / load accounts from a previous run
  --filter              Job filter expression, e.g. "traffic > 1e8"
  --system              Built-in system name or path to a system YAML file
  --system.base, --system.<section>.<field>
                        Inherit from another system and override individual fields
